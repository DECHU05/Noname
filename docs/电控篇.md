# CRTC 智能机器人小车项目日志 - 电控篇

## 一、底盘驱动（轮子驱动）

### 1. 底层环境与时钟配置

> 📅 9月27日-9月28日

开发初期在 STM32CubeMX 中完成基础初始化配置。期间遇到外部晶振（HSE）起振失败、程序卡死在 Error_Handler，排查后改用内部时钟（HSI）并通过 PLL X9 倍频，系统运行在 36MHz~72MHz。同时处理了 FreeRTOS 抢占 HAL 库 SysTick 导致的崩溃问题，将时基源改为 TIM4。

### 2. 电机驱动逻辑调试

> 📅 9月28日-10月1日

底盘驱动采用 4 个 TT 马达搭配 2 片 DRV8833 驱动模块，每片负责一侧的两只轮子。控制代码分三层：`Limit()` 把速度钳制在 ±100 以内，`Set_Motor()` 完成电机编号到引脚与定时器通道的映射，`Kinematics()` 把上层给出的前后速度与自转量分配到四轮。

四路电机的对应关系如下：

| 编号 | 位置 | 引脚 | 定时器通道 |
| --- | --- | --- | --- |
| M1 | 左前 | PA0 / PA1 | TIM2_CH1 / CH2 |
| M2 | 右前 | PA2 / PA3 | TIM2_CH3 / CH4 |
| M3 | 左后 | PA6 / PA7 | TIM3_CH1 / CH2 |
| M4 | 右后 | PB0 / PB1 | TIM3_CH3 / CH4 |

每路都用一对引脚做互补输出：正转时前一个通道出 PWM、后一个给 0，反转则两者对调，从根上避免 H 桥上下桥臂直通。

调试中出现电机只叫不转或卡顿蜂鸣。排查发现是仅用单引脚输出 PWM、H 桥上下桥臂直通短路，随后将方向引脚改为 PWM 互补输出（正转 PA0 出 PWM / PA1 给 0，反转对调）。

### 3. PWM 边界与供电优化

> 📅 10月10日-10月11日

全速运行时出现定时器溢出导致电机锁死。排查发现 PWM 占空比上限设置为 1000、而实际周期为 999，越界锁死，随即将映射公式修改为 speed * 9。

之后出现开机随机坏一个轮子。排查为 LM2596S 仅 2A 供电瓶颈、4 个电机启动瞬间电压暴跌所致，最终引入 XL4015（5A），并把整车供电统一为一组 7.4V 18650 电池组（两节串联）：全车只有这一个供电模块、一个输出接口，由 XL4015 降至 5V 供 PCA9685 、舵机 、两片 DRV8833，再经 STM32 板载 LDO 出 3.3V 供主控与接收器，各组降压模块与主控共地。

### 4. 驱动方案变更与控制逻辑重构

> 📅 10月11日-10月12日

结合路面起伏与对抗中可能出现的碰撞，团队决定将底盘方案从麦克纳姆轮变更为 65mm 胶轮，原有基于麦轮 X 型排布的全向解算代码已不适用。

针对胶轮底盘，电控组讨论了两种转向控制逻辑：一是利用左右两侧轮子的速度差实现原地旋转与转向（差速转向）；二是前轮舵机转向配合后轮动力驱动（类似常规车辆）。电控代码先为这两种转向方式预留了控制接口，最终按差速转向重写底层运动控制代码。

胶轮车不能横移，解算函数也随之从麦轮时代的三分量版本简化为两参数版本：左侧两轮同速、右侧两轮同速，两侧速度差就是转向量。

```
V_LF = V_LB = Vx + Omega     // 左侧
V_RF = V_RB = Vx - Omega     // 右侧
```

前进与自转是两个会互相抢功率的量。若满舵自转时仍给满前进，一侧轮子会到 100、另一侧只剩 20，车便画着弧线走。因此在解算前先按自转幅度给前进降额：

```c
if (Vx != 0) {
    int room = 100 - abs(Omega);   /* 自转越大，留给前进的余量越小 */
    Vx = Vx * room / 100;
}
```

自转通道另设死区与增益，避免松手后残留的微小偏移让车体缓慢漂移：

| 宏 | 取值 | 作用 |
| --- | --- | --- |
| `ROT_DEAD` | 25 | 自转死区，摇杆回中附近视为 0 |
| `ROT_GAIN` | 100 | 满舵输出比例（早期取 80） |

### 5. 车辆复装与电路重连

> 📅 10月14日-10月15日

原来那台麦轮加六舵机的车被拆解，重新走线并复装：拆车的原因是驱动模块数量不够用，现有的备用驱动没有针脚，需要先补焊才能使用。胶轮车的电路同步接线。

10 月 15 日，底座的漏电问题也已解决，电源部分按既定的单供电模块方案接好。

### 6. 装车阶段的电路收尾

> 📅 10月16日-10月18日

*   **10 月 18 日**：电容到货，按既定方案把主控（STM32）的供电线正式接到位，并加电容滤波。
*   胶轮底盘的差速转向代码适配完成，装车后进入整体联调。
*   装车联调中发现底盘“力量明显偏弱”。排查下来是两处限速叠加：指令速度只给了 60/100，而电机映射里 `pwm_val = speed * 9` 又把上限压在 90%，两级相乘后实际只发挥出约 **54%** 的电机能力。把指令速度改为满值 100 后动力恢复正常。
*   代码里保留了编译期开关 `MOTOR_SELF_TEST`，置 1 时上电逐个通道正转 2 秒、反转 2 秒，用于快速区分“某个轮子不转”是接线问题还是代码问题。
*   线缆按装车后的实际走向重新整理、固定。

## 二、机械臂控制（抓取）

### 1. 硬件选型与通信搭建

> 📅 9月28日-10月3日

机械臂执行端采用 6 个 SG90 舵机（5 自由度加夹爪），搭配 PCA9685 16 路 PWM 驱动板。STM32 通过 I2C 协议（PB6、PB7）与 PCA9685 通信，实现对多路舵机的集中控制。

### 2. 供电异常与硬件保护

> 📅 10月4日-10月9日

组装阶段发生两起烧毁事件：一是强行塞线导致 PCA9685 绿色电源端子接触不良引发短路，XL4015 触发保护后彻底烧毁；二是误将 5V 和 GND 反接，导致 STM32 板载 LDO 稳压芯片烧毁。

由此确立两条操作规范：通电前必用万用表测极性、先接 GND 再接 VCC。

### 3. PCA9685 驱动实现

> 📅 10月8日-10月9日

PCA9685 的驱动为自行编写（`pca9685.c`、`pca9685.h`）：初始化先复位，再按 `25MHz / (4096 × 50Hz) − 1 = 121`（`0x79`）写 `0xFE`，把 PWM 频率定在 50Hz；设置角度时通道 `ch` 的起始寄存器为 `0x06 + 4 × ch`。计数值 307 对应 90°、150 对应 45°、460 对应 135°。

### 4. 舵机故障排查

> 📅 10月10日-10月11日

后续联调测试中，机械臂最顶端的夹取舵机卡死，驱动模块温度急剧升高。排查确认该舵机本体损坏，PCA9685 驱动模块也因过流波及烧毁，电池电量被剧烈放电耗尽。随后替换备用模块，并暂时将机械臂转移至电脑供电。

### 5. 舵机角度标定与平滑过渡

> 📅 10月10日-10月12日

舵机全局上下限为 150 / 460 / 307，由 `limit_angle()` 在下发前钳制；各关节位置单独定义，腕部水平 / 垂直取 400 / 185（早期 307 / 150，实测伸不进镂空方块后改）。过渡由 `Smooth_Move_To()` 完成：把总时长按 20ms 拆步、线性插值逼近目标值，再下发六个通道。注明：这套参数是**六舵机时期**的取值，现役三舵机方案见下一节。

### 6. 控制方案的简化与迭代

> 📅 10月12日-10月15日

配合机械结构，电控组按三舵机两杆结构完成了控制逻辑的简化设计：三舵机安装在机械臂本体上，占用 PCA9685 的 0、1、2 通道；底座旋转舵机在结构上预留了安装位，通道 3 留作扩展，本轮不装。各车型共用同一套通道分配与同一份机械臂代码，不再分别维护。

三舵机分别接管夹爪（A）、大臂（B）与小臂（C）。上电时三个关节先归到中位（A = B = 307、C = 400），再开放操作。手感上没有把摇杆量直接当作目标角度，而是先压成“每 20 ms 走多少步”：轻推是微调、推到底是快走，中间留 20 的死区，速度上限设为每周期 6 步（约 300 单位/秒），避免一下甩到限位撞坏结构。

```c
#define ARM_STEP_DIV  20   /* 摇杆幅度 → 步长 */
#define ARM_STEP_MIN  20   /* 死区 */
#define ARM_STEP_MAX  6    /* 速度上限，防止甩到底 */
```

各关节的行程再单独限位，超出范围的角度在下发前就被钳住：

| 关节 | 初始位 `HOME_*` | 行程 `LIM_*` |
| --- | --- | --- |
| 夹爪 A | 307 | 200 – 450 |
| 大臂 B | 307 | 100 – 500 |
| 小臂 C | 400 | 150 – 500 |

### 7. 一键夹取流程

> 📅 10月18日

为减少操作手在抓取时的连续拨杆，给手柄的 L1 增加了一套一键夹取时序：按下后由程序走完整套动作，拆成九段，每段都有明确的退出条件。

| 段 | 动作 | 退出条件 |
| --- | --- | --- |
| T1 | 张开夹爪 | 600 ms |
| T2 | 下降至抓取位（B = 475、C = 150） | **到达目标位** 或 3 s 兜底 |
| T3 | 闭合夹取 | 800 ms |
| T4 | 夹紧停留 | 300 ms |
| T5 | 收至运输位（B = 250、C = 500），夹爪全程保持收紧 | **到达目标位** 或 3 s 兜底 |
| T6 | 到位后停顿 | 1 s |
| T7 | 张开夹爪放料 | 800 ms |
| T8 | 停顿 | 1 s |
| T9 | 三关节回到上电初始位 | **到达目标位** 或 3 s 兜底 |

其中“下降”与“收回”两段不是按固定时长空等：每 20 ms 调一次 `grab_move_toward()` 朝目标值逼近，再用 `grab_at_target()` 判断是否到位——到位立刻进入下一段，最长等 3 秒兜底。这样不论舵机负载轻重，动作都不会拖沓。

```c
/* L1 下降沿启动一次，按住不会反复触发 */
if (l1 == 1 && l1_prev == 0 && grab_state == 0) {
    grab_state = 1;
    grab_tick = 0;
}
```

自动流程执行期间函数返回 1，主循环据此跳过摇杆与 R1 的手动处理，只下发自动流程算出的角度，避免操作手的杆位把动作打乱。

## 三、遥控（PS2 手柄通信）

### 1. 通信协议配置与工程导入

> 📅 9月30日-10月2日

遥控单元采用 PS2 无线手柄及接收器，通信接口为软件 SPI（STM32 的 PB12~PB15 引脚）。开发初期将底层驱动库 ps2.c 导入工程后，因第三方库依赖 CubeMX 的 User Label，导致引脚宏定义缺失，随后在 ps2.h 中手动补齐引脚宏映射，解决编译报错。

### 2. 时序调试与数据读取

> 📅 10月2日-10月7日

联调时原有的 delay_us(8) 对现有低成本接收器而言过快，无法正常读取数据，改为 delay_us(15)。排查中发现手柄必须按下 Mode 键（红灯/绿灯常亮）才能输出 0~255 的平滑摇杆数据，后续将此作为遥控操作的标准前置动作。

### 3. 数据解算与电机驱动整合

> 📅 10月7日-10月10日

通信打通后将手柄数据与电机控制整合，在 while(1) 循环中以 20ms 周期刷新手柄数据，读取左右摇杆的三个分量：Vx = 128 − LY（前后）、Vy = LX − 128（平移）、Omega = 128 − RX（旋转）。三个分量各设 ±10 死区，把摇杆静止时的微小偏移视为 0；再统一按 × 80 / 128 缩放，限制在 80% 以内，最后调用底层电机驱动函数。

### 4. 手柄键位

> 📅 10月11日-10月15日

胶轮车不能横移，底盘只退化出“前进后退 + 左右转弯”两种输入。两个摇杆被解放出来交给机械臂和车体旋转——左右手各管机械臂的一段，抓夹交给肩键用食指操作：

| 按键 | 功能 |
| --- | --- |
| 左摇杆前后 | 机械臂大臂（B）——推上抬、推下压 |
| 右摇杆前后 | 机械臂小臂（C） |
| 右摇杆左右 | 车体自转（差速转向），取 `Omega = RX − 128` |
| 方向键 ↑ / ↓ | 底盘前进 / 后退 |
| R1 | 夹爪开合，按一次切换 |
| L1 | 一键自动夹取 |
| ANALOG（Mode）键 | 切换模拟模式，使左右摇杆可用 |

## 四、软件架构（FreeRTOS）

> 📅 10月12日-10月18日

工程基于 CubeMX 生成的 FreeRTOS 框架，功能拆成五个任务：`task_ps2`（High）每 20ms 刷新手柄、`task_classes`（AboveNormal）解算并驱动底盘、`task_arm`（Normal）机械臂与夹爪、`defaultTask`（Normal）、`task_debug`（Low）心跳灯。任务内等待统一用 `osDelay()` 而非 `HAL_Delay()`——后者空转等待占用 CPU ，会导致低优先级任务被忽略。

调试灯同时兼作驱动板自检：PCA9685 初始化成功后灯以 400 ms 慢闪，I2C 无响应时转为 100 ms 快闪。上电先静默 1.2 秒，等 `PCA9685_Init()` 执行完再开始闪，避免把初始化过程误判为故障。

**10 月 18 日**给手柄的 **L1** 加了一键自动夹取：按下后即可由程序走完“下压—闭合—抬起”的完整时序，操作手不用再连续拨动摇杆和按键，抓取节奏更稳定，也降低了误操作的概率。
