# CRTC 智能机器人小车项目日志 - 电控篇

## 一、底盘驱动（轮子驱动）

### 1. 底层环境与时钟配置
开发初期，我们在 STM32CubeMX 中完成了基础初始化配置。期间遇到了外部晶振（HSE）起振失败导致程序卡死在 `Error_Handler` 的问题，排查后，我们改用内部时钟（HSI）并通过 PLL X9 倍频，使系统稳定运行在 36MHz~72MHz。同时处理了 FreeRTOS 抢占 HAL 库 SysTick 导致的崩溃问题，将时基源改为 TIM4。

### 2. 电机驱动逻辑调试
底盘驱动最初采用 4 个 TT 马达搭配 2 片 DRV8833 驱动模块，运动算法为麦克纳姆轮 X 型排布逆运动学解算。通过读取摇杆的 Vx、Vy 和 Omega 值，将其转换为四个轮子的独立速度。

调试中遇到了电机只叫不转或卡顿蜂鸣的问题。经排查，原因是仅用单引脚输出 PWM，导致 H 桥上下桥臂直通短路。后来将方向引脚配置为 PWM 互补输出（正转 PA0 出 PWM / PA1 给 0，反转则对调），解决了这一问题。

### 3. 供电优化与硬件连接迭代
在全速运行时，我们遇到了定时器溢出导致电机锁死的情况。排查发现，PWM 占空比上限设置为 1000，但实际周期为 999，越界导致锁死。随后将映射公式修改为 `speed * 9`，避开了上限。

之后又遇到了开机随机坏一个轮子的现象。经排查，是 LM2596S 仅 2A 供电瓶颈，带 4 个电机启动瞬间电压暴跌所致。最终我们引入了 XL4015（5A），采用双电源隔离加共地架构解决。硬件连接上，抛弃了容易接触不良的面板和杜邦线，改用洞洞板焊接、螺栓固定和电工胶布绝缘防脱。

### 4. 驱动方案变更与控制逻辑重构（开发中）
结合赛事场地包含高台、坡道、台阶以及规则中允许“挤压”的物理对抗需求，团队决定将底盘方案从麦克纳姆轮变更为 60mm 胶轮方案。但因为方案的更改，原有基于麦轮 X 型排布的全向解算代码已不适用。

针对胶轮底盘，电控组讨论了两种转向控制逻辑：一是利用左右两侧轮子的速度差实现原地旋转与转向（差速转向）；二是采用前轮舵机转向配合后轮动力驱动（类似常规车辆）。目前，电控代码已针对这两种可能的转向方式预留了控制接口，待底盘机械结构最终定型后，我们将重新编写适配 60mm 胶轮的底层运动控制代码，这部分工作目前正在跟进。


## 二、机械臂控制（抓取）

### 1. 硬件选型与通信搭建
机械臂执行端最初采用 6 个 SG90 舵机（5自由度加夹爪），搭配 PCA9685 16路 PWM 驱动板。STM32 通过 I2C 协议（PB6、PB7）与 PCA9685 进行通信，以实现对多路舵机的集中控制。

### 2. 供电异常与硬件保护
组装阶段发生了两起烧毁事件。其一为强行塞线导致 PCA9685 绿色电源端子接触不良引发短路，XL4015 触发保护后彻底烧毁；其二为误将 5V 和 GND 反接，导致 STM32 板载 LDO 稳压芯片烧毁。

由此我们确立了通电前必用万用表测极性、先接 GND 再接 VCC 的操作规范。在动力供给方面，我们确立了三路隔离供电方案，确保主控不死机且动力之间不互相干扰。

### 3. 舵机故障排查与二次排障
在后续的联调测试中，机械臂最顶端的夹取舵机出现了卡死现象，导致驱动模块温度急剧升高。经排查，不仅该舵机本体损坏，PCA9685 驱动模块也因过流波及而烧毁，同时电池电量被剧烈放电耗尽。我们随后紧急替换了备用模块，并暂时将机械臂转移至电脑供电，以优先确认其他结构的完好性。

### 4. 控制方案的简化与迭代（已达成）
经过实际功能评估与任务推演，电控组决定配合机械结构，将原本的六舵机方案缩减为三舵机结构（注：三舵机均安装在机械臂本体上，底座旋转功能可能还需要额外预留一个舵机通道）。控制逻辑在软件层面也进行了简化，虽然减少了机械臂的物理自由度，但提升了系统的稳定性和供电安全性，也大大降低了操作手的操作难度。


## 三、遥控（PS2 手柄通信）

### 1. 通信协议配置与工程导入
遥控单元采用 PS2 无线手柄及接收器，通信接口分配为软件 SPI（STM32 的 PB12~PB15 引脚）。开发初期，我们将底层驱动库 `ps2.c` 导入工程后，因第三方库依赖 CubeMX 的 User Label，导致引脚宏定义缺失。随后在 `ps2.h` 中手动补齐了引脚宏映射，解决了编译报错。

### 2. 时序调试与数据读取
联调时，原有的 `delay_us(8)` 时序对于现有的低成本接收器而言过快，导致无法正常读取数据，后来我们将其修改为了 `delay_us(15)`。操作层面，通过排查我们发现了手柄必须按下 Mode 键（红灯/绿灯常亮）才能输出 0~255 的平滑摇杆数据，后续将此作为遥控操作的标准前置动作。

### 3. 数据解算与电机驱动整合
在通信打通后，我们将手柄数据与电机控制进行了整合。控制逻辑为：在 `while(1)` 循环中以 20ms 的周期刷新手柄数据，读取左摇杆垂直轴（LY）模拟量，减去中心值（128）得到偏移量。为了防止摇杆静止时的微小偏移影响电机，我们将偏移量在 -10 到 10 之间的数据全部视为了 0，作为死区处理；并将有效偏移量设定为在 -100 到 100 区间的速度值，调用底层的电机驱动函数，实现了左摇杆对前轮的正反转与速度的直接控制。

### 4. 基础手动功能设置
在机械臂的操作上，手柄功能键设定分工如下：
*   三角键：直接控制机械爪的夹取与松开。
*   方形键 / 圆形键：控制机械臂底座的逆时针 / 顺时针旋转（如果底座加装了额外舵机）。
*   叉键：控制夹取头旋转 90 度。

**设计逻辑**：通过将机械臂的夹取、底座旋转和夹头旋转分别映射到不同按键，保证了功能操作的独立性。操作手在抓取时，左手负责底盘，右手负责机械臂，实现左右手分工明确、互不干扰，有效减少了比赛中的操作失误。


## 四、视觉模块（探索性功能）

### 1. 硬件引入与识别目标
为了推进半自动化作业目标，团队采购了 K230D 视觉开发板及配套摄像头模块。初步计划是利用视觉识别场地中的道具，主要目标是识别黄色方块（能量核心）与白色方块（能量单元）。

### 2. 控制逻辑与预期效果
设想是当视觉模块识别到目标方块后，将坐标信息发送给 STM32 主控。主控尝试控制底盘进行自动对齐，并驱动机械臂执行抓取动作，实现半自动化。

### 3. 保守的推进策略
由于视觉识别受现场光线、角度等不确定因素影响较大，团队采取保守策略：如果调校顺利且识别稳定，则作为进阶功能展示；如果在实际场地测试中不稳定，则退回纯 PS2 手柄手动控制，确保基础抓取功能不受影响。
