# CRTC 智能机器人小车项目日志 - 电控篇

## 一、底盘驱动（轮子驱动）

### 1. 底层环境与时钟配置

> 📅 9月27日-9月28日

开发初期在 STM32CubeMX 中完成基础初始化配置。期间遇到外部晶振（HSE）起振失败、程序卡死在 Error_Handler，排查后改用内部时钟（HSI）并通过 PLL X9 倍频，系统运行在 36MHz~72MHz。同时处理了 FreeRTOS 抢占 HAL 库 SysTick 导致的崩溃问题，将时基源改为 TIM4。

### 2. 电机驱动逻辑调试

> 📅 9月28日-10月1日

底盘驱动采用 4 个 TT 马达搭配 2 片 DRV8833 驱动模块。控制代码分三层：`Limit()` 限幅，`Set_Motor()` 换算 PWM 并写方向脚，`Kinematics()` 按 X 型排布把前后、左右、旋转三个分量叠加到四轮。

调试中出现电机只叫不转或卡顿蜂鸣。排查发现是仅用单引脚输出 PWM、H 桥上下桥臂直通短路，随后将方向引脚改为 PWM 互补输出（正转 PA0 出 PWM / PA1 给 0，反转对调）。

### 3. PWM 边界与供电优化

> 📅 10月10日-10月11日

全速运行时出现定时器溢出导致电机锁死。排查发现 PWM 占空比上限设置为 1000、而实际周期为 999，越界锁死，随即将映射公式修改为 speed * 9。

之后出现开机随机坏一个轮子。排查为 LM2596S 仅 2A 供电瓶颈、4 个电机启动瞬间电压暴跌所致，最终引入 XL4015（5A），并把整车供电统一为一组 7.4V 18650 电池组（两节串联）：全车只有这一个供电模块、一个输出接口，由 XL4015 降至 6V 供 PCA9685 与舵机、降至 5V 供两片 DRV8833，再经 STM32 板载 LDO 出 3.3V 供主控与接收器，各组降压模块与主控共地。硬件连接上抛弃了容易接触不良的面板和杜邦线，改用洞洞板焊接、螺栓固定、电工胶布绝缘防脱。

### 4. 驱动方案变更与控制逻辑重构（开发中）

> 📅 10月11日-10月12日

结合场地的高台、坡道、台阶以及规则中允许“挤压”的对抗需求，团队决定将底盘方案从麦克纳姆轮变更为 60mm 胶轮，原有基于麦轮 X 型排布的全向解算代码已不适用。

针对胶轮底盘，电控组讨论了两种转向控制逻辑：一是利用左右两侧轮子的速度差实现原地旋转与转向（差速转向）；二是前轮舵机转向配合后轮动力驱动（类似常规车辆）。目前电控代码已为这两种转向方式预留控制接口，待底盘机械结构定型后重新编写适配 60mm 胶轮的底层运动控制代码。

### 5. 底盘旋转功能调通

> 📅 10月12日

底盘原地旋转功能调通。右摇杆左右向接入逆运动学解算的 Omega 分量，四个轮子按 X 型解算得到“左侧反转、右侧正转”的速度组合，车体可原地逆时针或顺时针旋转。

## 二、机械臂控制（抓取）

### 1. 硬件选型与通信搭建

> 📅 9月28日-10月3日

机械臂执行端采用 6 个 SG90 舵机（5 自由度加夹爪），搭配 PCA9685 16 路 PWM 驱动板。STM32 通过 I2C 协议（PB6、PB7）与 PCA9685 通信，实现对多路舵机的集中控制。

### 2. 供电异常与硬件保护

> 📅 10月4日-10月9日

组装阶段发生两起烧毁事件：一是强行塞线导致 PCA9685 绿色电源端子接触不良引发短路，XL4015 触发保护后彻底烧毁；二是误将 5V 和 GND 反接，导致 STM32 板载 LDO 稳压芯片烧毁。

由此确立两条操作规范：通电前必用万用表测极性、先接 GND 再接 VCC。

### 3. PCA9685 驱动实现

> 📅 10月8日-10月9日

PCA9685 的驱动为自行编写（`pca9685.c`、`pca9685.h`）：初始化先复位，再按 `25MHz / (4096 × 50Hz) − 1 = 121`（`0x79`）写 `0xFE`，把 PWM 频率定在 50Hz；设置角度时通道 `ch` 的起始寄存器为 `0x06 + 4 × ch`。计数值 307 对应 90°、150 对应 45°、460 对应 135°。

### 4. 舵机故障排查

> 📅 10月10日-10月11日

后续联调测试中，机械臂最顶端的夹取舵机卡死，驱动模块温度急剧升高。排查确认该舵机本体损坏，PCA9685 驱动模块也因过流波及烧毁，电池电量被剧烈放电耗尽。随后替换备用模块，并暂时将机械臂转移至电脑供电。

### 5. 舵机角度标定与平滑过渡

> 📅 10月10日-10月12日

舵机全局上下限为 150 / 460 / 307，由 `limit_angle()` 在下发前钳制；各关节位置单独定义，腕部水平 / 垂直取 400 / 185（早期 307 / 150，实测伸不进镂空方块后改）。过渡由 `Smooth_Move_To()` 完成：把总时长按 20ms 拆步、线性插值逼近目标值，再下发六个通道。

### 6. 控制方案的简化与迭代（已定型，尚未投用）

> 📅 10月12日

配合机械结构，电控组按三舵机两杆结构完成了控制逻辑的简化设计：三舵机安装在机械臂本体上，底座旋转另需一个舵机通道，共四路。该结构刚刚定型，底座尚未制作完成，暂未投入使用，车上现役仍为六舵机方案。

## 三、遥控（PS2 手柄通信）

### 1. 通信协议配置与工程导入

> 📅 9月30日-10月2日

遥控单元采用 PS2 无线手柄及接收器，通信接口为软件 SPI（STM32 的 PB12~PB15 引脚）。开发初期将底层驱动库 ps2.c 导入工程后，因第三方库依赖 CubeMX 的 User Label，导致引脚宏定义缺失，随后在 ps2.h 中手动补齐引脚宏映射，解决编译报错。

### 2. 时序调试与数据读取

> 📅 10月2日-10月7日

联调时原有的 delay_us(8) 对现有低成本接收器而言过快，无法正常读取数据，改为 delay_us(15)。排查中发现手柄必须按下 Mode 键（红灯/绿灯常亮）才能输出 0~255 的平滑摇杆数据，后续将此作为遥控操作的标准前置动作。

### 3. 数据解算与电机驱动整合

> 📅 10月7日-10月10日

通信打通后将手柄数据与电机控制整合，在 while(1) 循环中以 20ms 周期刷新手柄数据，读取左右摇杆的三个分量：Vx = 128 − LY（前后）、Vy = LX − 128（平移）、Omega = 128 − RX（旋转）。三个分量各设 ±10 死区，把摇杆静止时的微小偏移视为 0；再统一按 × 80 / 128 缩放，限制在 80% 以内，最后调用底层电机驱动函数。

### 4. 手柄键位重排

> 📅 10月11日-10月12日

对手柄键位做了整体重排，底盘与机械臂的动作分配如下：

*   左摇杆：底盘前后、左右移动。
*   右摇杆左右向：车体逆时针 / 顺时针旋转。
*   右摇杆前后向：机械臂下压 / 恢复。
*   方向键（十字键）：底盘前后左右微调。
*   L1 / R1：机械臂底座逆时针 / 顺时针旋转（如果底座加装了额外舵机）。
*   三角键：机械爪夹取 / 松开。
*   叉键：夹取头旋转 90 度。
*   ANALOG（Mode）键：切换模拟模式，使左右摇杆可用。

操作手左手负责底盘（左摇杆走位、方向键微调），右手负责机械臂。

## 四、软件架构（FreeRTOS）

> 📅 10月10日-10月12日

工程基于 CubeMX 生成的 FreeRTOS 框架，功能拆成五个任务：`task_ps2`（High）每 20ms 刷新手柄、`task_classes`（AboveNormal）解算并驱动底盘、`task_arm`（Normal）机械臂与夹爪、`defaultTask`（Normal）、`task_debug`（Low）心跳灯。任务内等待统一用 `osDelay()` 而非 `HAL_Delay()`（后者空转等待会占着 CPU 不放，以至于忽略低优先级任务）

## 五、视觉模块（探索性功能）

### 1. 硬件引入与识别目标

> 📅 10月11日

为推进半自动化作业，团队采购 K230D 视觉开发板及配套摄像头模块。初步计划是利用视觉识别场地中的道具，主要目标是黄色方块（能量核心）与白色方块（能量单元）。

### 2. 控制逻辑与预期效果

> 📅 10月12日

设想是视觉模块识别到目标方块后，将坐标信息发送给 STM32 主控，主控控制底盘自动对齐并驱动机械臂执行抓取动作，实现半自动化。

### 3. 保守的推进策略

> 📅 10月12日

视觉识别受现场光线、角度等不确定因素影响较大，团队采取保守策略：调校顺利、识别稳定则作为进阶功能展示；实际场地测试不稳定则退回纯 PS2 手柄手动控制，确保基础抓取功能不受影响。
